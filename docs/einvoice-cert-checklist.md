# EINV 檢測 checklist（Turnkey 上線前自行檢測作業 V4.8）

> **範圍**：潤樋是 B2S 存證營業人，不做 B2B 交換發票。所以 A/B 系列（10 情境）跳過。
> **目標**：完成 phase A + B + C 產出檢測報告 → 上傳 EINV → 拿到上線通行碼。
> **開始日**：2026-08-07

---

## Phase A — 前置作業檢測（4 項）

系統面自動化能力驗證，不是逐張開票。ERP 端 v2.18.0 (commit d394627) 已有這些功能，本階段是**驗證它們真的能運作 + 準備截圖佐證**。

| # | 項目 | 需求 | ERP 現況 | 驗證方式 | 截圖 |
|---|---|---|---|---|---|
| A1 | 字軌檢核 | 開票號碼不在配號池內要擋 | `einvoice.service.ts` allocate() 檢查 | 手動打錯號碼 or 用光後開新張 | 待做 |
| A2 | 重號檢核 | 同號碼再用一次要擋 | Prisma unique + service check | 手動改 DB 塞重複 → 開票 | 待做 |
| A3 | 漏上傳每日對帳 | 每天固定時間對帳 + 告警 | `reconcile.ts` + `einvoice-sync.ts` cron 03:30 | 手動刪掉 SendFile 的 XML → 隔天 03:30 看 LINE 告警 | 待做 |
| A4 | Turnkey E 狀態異常告警 | Turnkey 回 E 狀態能被系統辨識 + 通知 | `reconcile.ts` hasAlerts() + sendReconcileAlerts() | 塞一個假錯誤 DownCast 檔 → 觀察是否更新 status | 待做 |

**預估時間**：0.5 天

## Phase C — 壓力測試 1000 張

- 寫 CLI 批次工具 `src/tools/pressure-test-invoices.ts`
- 產生 1000 張 B2C 應稅小額測試發票
- 觀察 Turnkey 處理速度（每 15 min 一批）+ EINV 收到率
- 記錄異常/失敗
- 出報告：處理總時間、SendFile 成功數、EINV 對帳成功數

**預估時間**：1-2 天（含批次工具開發 + 執行 + 觀察）

---

## Phase D — 撰寫檢測報告

- 財政部提供的檢測報告 Word 模板（若無，自製 PDF）
- 每情境貼截圖 + 系統操作紀錄 + EINV 回覆狀態
- 前置 4 項 + 18 情境 + 壓力測試 = 23 個章節

**預估時間**：1 天

---

## Phase E — 上傳報告等審核

- EINV 平台 → 上傳檢測報告
- 承辦人員審核（3-7 個工作天）
- 通過後核發**上線通行碼**
